# 升级与兼容安全策略（dsh-remote）

> 2026-10-24 事故（0.7.5 撤回）后立的规矩：**任何升级/优化都不得让现有用户的会话失效或变砖**。
> 本文是发布前的强制门禁，与 `RELEASE-POLICY.md` 一起使用；不满足门禁的版本不准进 `latest`。

---

## 一、两条会话必须都保住

| 会话 | 存在哪 | 升级时允许发生什么 | 绝不允许 |
|---|---|---|---|
| **登录会话**（账号 JWT / 手机 token） | 手机浏览器 / 电脑端 | 服务端重启、router 重启后继续可用（隧道自动重连） | 无理由把用户踢下线、强制重新登录 |
| **E2EE 加密会话**（手机 ↔ 电脑桥） | 桥内存 + 手机页面内存/本地 | 桥重启后**最多要求自动重新握手一次**（用户无感） | 出现「无法解密」且不自动恢复；复用旧计数解新帧 |

## 二、E2EE 会话升级规则（0.7.5 事故根因，硬性）

1. **会话库必须带版本号**（`.e2ee-sessions.enc` 内 `v`）。版本不符 → **整库作废**，绝不尝试兼容解析。
2. **恢复的会话一律标记「需重新握手」**（`verified=false` + `restoredNeedsHandshake=true`）：
   - 桥只允许它们走控制通道重新握手/探测，**不允许直接开数据 WS**；
   - **严禁恢复旧收发计数**（`p2b/b2p`）：旧计数落后一个 flush 就会让下一次握手误判 nonce 重放。
3. 解封失败（AEAD 失败/nonce 重放/会话缺失）必须显式回 **`retryable:true` + `action:"rehandshake"`** 信号，
   由手机自动重建会话；**绝不静默降级、绝不显示无法恢复的「无法解密」**。
4. 协议版本（`e2ee-v2` / caps / salt / epoch）不一致时，返回明确的「需重新握手/升级客户端」错误码，
   不得按旧协议硬解。
5. 会话库只存**会话材料**，不存 MK；文件 0600、AES-256-GCM、原子写；解不开就删（见 `e2ee-client.mjs`）。

## 三、服务端/客户端兼容规则

1. **只增不改**：企业端/中继接口字段只增不删、不改语义；客户端读不到新字段必须有兜底（feature-detect）。
2. **旧客户端可用**：新服务端上线后，上一版（至少 2 个次版本内）的客户端必须继续可用；
   不允许"必须升级客户端才能用"的破坏性变更（如换协议不兼容旧版）。
3. **旧服务端可用**：新客户端连旧服务端时，缺字段/旧行为必须优雅降级（如 `offer_claim_hours` 缺失时前端兜底）。
4. **手机页面（native.html）与服务端一起发**：旧页面连新服务端、新页面连旧服务端都要能工作；
   新 API 一律"失败静默/降级"，不得阻塞登录、设备列表、支付。
5. **登录态**：JWT 里的 `tv` 缺失视为 0（不追溯登出）；只有改密/管理员重置才 bump；
   **令牌轮换/重新登录不得关闭已建立隧道**（jti 黑名单只拦新连接，隧道只受 `token_version` 约束）。

## 四、发布门禁（每次发版逐项打勾）

### 4.1 代码与测试
- [ ] `npm run check` 通过
- [ ] `test:bridge` / `test:plugin` / `test:router` 全绿（含升级兼容用例：
      旧 JWT、旧会话库版本、恢复会话必须重新握手、旧字段缺失降级）
- [ ] 影响 E2EE 的改动必须附**升级场景测试**：桥重启后旧会话 → 重新握手 → 数据流恢复

### 4.2 发布顺序（禁止跳步）
1. 先发 **beta/alpha**（npm `--tag beta`，不建 GitHub Release、不动 `latest`）；
2. 作者真机回归 + 至少 1 天观察（可先只让自己/内测用）；
3. 再发正式：`latest` + GitHub Release + 市场（市场自动跟 npm latest）；
4. 正式包发布后 **24h 内保留回滚路径**：npm `latest` 指回上一稳定版、删除新 Release（`latest/download` 回到旧版）。

### 4.3 真机回归清单（E2EE 必测）
- [ ] 手机已登录状态下，电脑端重启桥 → 手机刷新/自动恢复，**无需重新登录**；
- [ ] 桥重启后最多要求一次「重新解锁/自动握手」，页面能恢复（不得停在「无法解密」）；
- [ ] 手机强刷 3 次 / 关闭再打开，会话与历史都正常；
- [ ] 另一台设备同时在线不受影响；
- [ ] 手机页面老缓存（强刷前）仍能打开设备（向后兼容）。

### 4.4 服务端部署（不影响现有会话）
- [ ] 只新增表/列/字段，不改既有字段语义；
- [ ] 重启顺序：enterprise → admin → router（router 重启会让桥重连，属预期）；
- [ ] 部署后验证：老 token 仍能访问、设备在线、支付/领取正常；
- [ ] 回滚：代码备份目录 + 功能级开关（如 `DSH_ROUTER_REVOKE_JTI_CLOSE`、`DSH_ROUTER_PLAN_OVERRIDE=0`）。

## 五、回滚 SOP（发现会话被破坏时 10 分钟内可退）

1. npm：`npm dist-tag add <pkg>@<上一稳定版> latest`；对新版本 `npm deprecate`；
2. GitHub：删除问题版本的 Release（`latest/download` 自动回到上一版）+ 删除 tag；
3. 插件市场：无需操作（跟随 npm latest）；
4. 手机页面：覆盖回上一版 `native.html`（docker cp）；
5. 桥：用户机器上可回退本地代码（`~/.dsh-remote` 备份目录）或安装指定旧版本；
6. 记录到内部部署文档，复盘写进本节。

## 六、0.7.5 事故结论（供复盘引用）

- 现象：手机远程页「无法解密」、历史事件流 cursor 错乱；另一设备正常；重新登录无效。
- 根因：0.7.5 新增 E2EE 会话加密落盘，桥重启后**恢复了计数过期的会话并直接复用** →
  手机用新计数加密、桥按旧计数解 → nonce 重放/解不开；坏票存在手机本地，故重登不清。
- 处置：删除桥会话库 + 关闭持久化 → 恢复；0.7.5 npm/GitHub Release 全量撤回。
- 整改：本文件的 §二/§四；0.7.6 起恢复的会话必须重新握手、不复用旧计数。
